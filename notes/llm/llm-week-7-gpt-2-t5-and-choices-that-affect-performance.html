0. Roadmap of the week

Weeks 3 and 4 gave us two kinds of pre-trained models: GPT (decoder, reads left to right, good at generating) and BERT (encoder, reads both ways, good at understanding). This week asks three connected questions:

  1. Can we combine both? Yes: encoder-decoder models such as BART and T5.
  2. Can one pre-trained model do many tasks without being retrained for each? GPT-2 says yes, using only a prompt (zero-shot).
  3. Which design choices really matter? The T5 study changes one thing at a time (architecture, objective, data, fine-tuning method, multi-task mixing, scale) and measures the effect on the same benchmarks.

1.2 BART: Bidirectional and AutoRegressive Transformer

Put a BERT-like encoder and a GPT-like decoder together. The decoder is connected to the encoder through cross-attention (every decoder layer looks at the encoder output).

Corrupted text
x₁, [mask], …, x_T
→
Encoder
bidirectional self-attention
→ cross-attention →
Decoder
masked self-attention + cross-attention
→
Original text
x₁, x₂, …, x_T
BART is a denoising autoencoder: corrupt the input, then rebuild the whole clean text.
  • It is a vanilla Transformer, with the GELU activation function.
  • The input is corrupted in several ways: random masking, token deletion, document rotation and so on.
  • The encoder reads the corrupted sequence. The decoder predicts the entire original sequence and the loss is computed over all of it (as in GPT).

1.3 The five BART corruptions (lecture summary)

Take the original text A B C D E. In every case the decoder must output the full A B C D E.

CorruptionEncoder seesWhat the model must learn
Token maskingA [M] C [M] EGuess single words from both sides (BERT-style)
Token deletionA C EFind where words are missing as well as what they were
Text infillingA [M] EOne mask hides a whole span (length from Poisson, mean 3, can be 0): guess how many tokens are missing
Sentence permutationsentences shuffledRestore the sentence order
Document rotationC D E A BFind the true start of the document
BART vs T5 (preview)BART rebuilds the whole clean text. T5 (section 5) outputs only the missing spans, so its target is much shorter and cheaper to decode.

2. GPT-2: prompting a language model (Module 1)

2.1 The cost of fine-tuning

Models like BERT, GPT and BART are fine-tuned separately for each task: we keep one copy of the model per task and train it on that task's labelled data. This is costly (thousands of labelled examples per task, one model copy per task) and some tasks do not have enough labels. It is also unlike humans: once we understand language, we can be given a book and asked ("prompted") to summarize it, with no supervised training.

$$\text{Fine-tuning loss: }\ \mathcal L=-\sum_{i}\log P(y_i\mid x_i;\Theta,W_{\text{task}})\qquad(\Delta\Theta\neq0\text{ for every task})$$

2.2 Zero-shot transfer: put the task in the input

A plain language model learns $p(\text{output}\mid\text{input})$. GPT-2 changes it to

$$p(\text{output}\mid\text{input},\text{task})$$

where the task is just an instruction in plain words prepended (or appended) to the input at inference time. Nothing is trained; the weights do not change ($\Delta\Theta=0$). Example from the slide: after the text "I enjoyed watching the transformer movie along with my ...", append TL;DR: and the model continues with a short summary ("Watched the transformer movie").

2.3 Why can this work at all?

WebText is so varied that it already contains natural "demonstrations" of tasks: a French sentence followed by its English translation, an article followed by "TL;DR:". Predicting the next token well forces the model to learn these patterns, so a prompt can trigger them. The slide says exactly this about translation: naturally occurring demonstrations of English-to-French and French-to-English are found throughout WebText.

2.4 Causal language modelling: the math

Chain rule. The probability of a whole sentence is built from next-token probabilities: $P(A,B,C)=P(A)\,P(B\mid A)\,P(C\mid A,B)$. So

$$P(X)=\prod_{i=1}^{N}P(x_i\mid x_{\lt i};\Theta),\qquad \mathcal L_{\text{CLM}}=-\sum_{i=1}^{N}\log P(x_i\mid x_{\lt i};\Theta)$$

Training minimizes this negative log-likelihood. To generate: the model produces a logit (raw score) for each word of the vocabulary, softmax turns the scores into probabilities, we pick a token (Week 4 decoding), append it and repeat.

2.5 Model, data and scale

  • Scale up both model and data. GPT (110M parameters) to GPT-2 (1.5B): layers about 4×, parameters about 10×.
  • Data: WebText. Outbound links from Reddit with at least 3 karma, excluding Wikipedia (to keep diversity and quality). About 8 million web pages, 40 GB of text. Karma is a cheap human quality filter.
  • Tokenizer: byte-level BPE, vocabulary 50,257 (256 byte symbols + about 50,000 merges + 1 end-of-text token). Byte level means any text in any language can be written, so there is never an unknown token.
  • Training: causal language modelling, context window 1024, batch size 512 sequences (= 524,288 tokens per step).

2.6 Metrics: perplexity and bits per character

$$\text{PP}(X)=\exp\!\Big(-\frac1N\sum_{i=1}^{N}\log P(x_i\mid x_{\lt i})\Big)\ \ (\text{lower is better}),\qquad \text{BPC}=-\frac1{N_{\text{char}}}\sum\log_2P(c_i\mid c_{\lt i})$$
Worked example (my calculation)A 4-token sentence gets probabilities 0.5, 0.25, 0.1, 0.2. Natural logs: −0.693, −1.386, −2.303, −1.609, sum −5.991. Average = 5.991/4 = 1.498, so PP = e1.498 ≈ 4.47. Check: $(0.5\cdot0.25\cdot0.1\cdot0.2)^{-1/4}=0.0025^{-0.25}=4.47$. Meaning: at each step the model is as unsure as if it chose among about 4.5 equally likely words. Perfect prediction (all probabilities 1) gives PP = 1.
Why exp? The loss is an average negative log-probability; exp turns it back into "number of choices".
BPC: if each of 8 characters gets probability 1/4, each costs $\log_2 4=2$ bits, so BPC = 2.

4. The Text-to-Text framework and C4 (Module 2, L32)

4.1 Everything is text in, text out

Formulate every NLP problem as "text in, text out". A task-specific prefix is prepended to the input to say which task it is. One model, one loss (cross-entropy over output tokens), no special output heads.

Evaluation metrics depend on the task: BLEU for translation, ROUGE for summarization, Exact-Match and F1 for question answering (GLUE and SuperGLUE report an average score).

4.2 The C4 dataset

PropertyValue
NameColossal Clean Crawled Corpus (C4)
Sizeabout 750 GB (the slide tables write 745 GB), 300M documents, 156 billion tokens
LanguageMainly English
Compared with BERT's pre-training dataAbout 52 times bigger
TokenizerSentencePiece (Unigram model, Week 5), vocabulary 32,000

How it is cleaned (details from the lecture summary): start from Common Crawl; keep only lines ending in . ! ? or a quote; drop pages with fewer than 5 sentences; drop lines containing code characters such as { }; drop pages containing words from a bad-words list; remove duplicate 3-sentence spans; keep only English (langdetect confidence above 0.99). Each filter has a reason: punctuation keeps real sentences, 5+ sentences drops stubs, no braces removes code, the bad-words list removes offensive pages, deduplication stops repeated text (which causes memorization, see section 8), and language detection keeps English only.

SentencePiece recap. It treats text as a raw stream of characters, writing a space as the visible symbol ▁, so it is language-agnostic and decoding is lossless ("▁New ▁York" becomes "New York" again).

5.2 The denoising objective: span corruption

Analogous to MLM, but replace a random span of tokens by a single sentinel token. The decoder must output the missing spans, each introduced by its sentinel, and a final sentinel to end.

Original textWhat sets this mission apart is the pivotal role of artificial intelligence (AI) in guiding the spacecraft during its critical descent to the moon's surface.
Input (encoder)What sets this <w> is the pivotal role of artificial <x> (AI) in guiding the spacecraft during its <y> to the moon's surface.
Target (decoder)<w> mission apart <x> intelligence <y> critical descent <z>
Slide example. Three spans were removed, so the target holds three sentinels plus one final sentinel.

The loss is cross-entropy over the target tokens only: $\mathcal L=-\sum_j\log P(y_j\mid y_{\lt j},\text{Encoder}(\tilde X))$.

Why it is cheap. The decoder writes only the missing words, not the whole sentence, so the target is short. This lowers computational cost and training time. (My calculation: with $N=512$, 15% corrupted and mean span 3: corrupted tokens $=0.15\times512\approx77$; spans $\approx77/3\approx26$; encoder input $\approx512-77+26=461$ tokens; decoder target $\approx77+26+1=104$ tokens.)

5.3 Pre-training budget (full derivation)

$$\text{tokens per batch}=512\times128=2^{9}\times2^{7}=2^{16}=65{,}536$$ $$\text{steps}=2^{19}=524{,}288$$ $$\text{total tokens}=2^{19}\times2^{16}=2^{35}=34{,}359{,}738{,}368\approx34\text{ B}$$

Context length 512, batch size 128. 34B tokens is only a fraction of C4's 156B ($34/156\approx22\%$), so the baseline does not even finish one epoch: every example is seen at most once. (BERT was trained on 137B tokens and RoBERTa on 2.2T tokens, so the baseline is much smaller; the slide calls 34B "a reasonable size for the baseline" given the compute budget and the many experiments to run.)

5.4 Optimizer and learning rate

  • AdaFactor optimizer (needs less memory than Adam).
  • Inverse square-root schedule with warm-up $k=10^4$:
$$\eta(n)=\frac{1}{\sqrt{\max(n,k)}},\qquad k=10^4$$

Reading it. For $n\le10^4$ the max is $k$, so $\eta=1/\sqrt{10^4}=1/100=0.01$ (flat). After that $\max(n,k)=n$, so $\eta(n)=1/\sqrt n=0.01/\sqrt{n/10^4}$: it falls slowly. Check: $n=4\times10^4\Rightarrow0.01/\sqrt4=0.005$; $n=10^6\Rightarrow1/1000=0.001$. The rate halves each time the step count grows 4 times.

6. Architectures and attention masks (Module 4)

6.1 Three structures under study

Dark cells mean self-attention is allowed; light cells mean it is not. Rows are the token that is reading, columns are the tokens it may look at.

Fully visible (BERT / encoder)
Causal (language model / decoder)
Causal with prefix (Prefix LM)
  • Encoder-decoder: the encoder is fully visible; the decoder is causal and cross-attends to the encoder.
  • Language model (decoder-only): one stack, causal mask. Input and output are concatenated into one sequence.
  • Prefix LM (decoder-only): the first part (the prefix, = the task input) is fully visible, the rest (the output) is causal.

6.2 Prefix language modelling

Example input: summarize the following: I enjoyed watching the transformer movie along with my .... We want the input to be attended bidirectionally and the task output generated autoregressively. So we can either (a) use the encoder for the input and the decoder for the output, or (b) use a decoder with the prefix mask instead of the causal mask, with the task prepended to the input. During pre-training on C4, take a random span of text and randomly split it into two parts: one is the prefix, the other the target.

6.3 How do we compare an encoder-decoder with a decoder-only model?

Two possible criteria: the number of parameters $P$ (the slide uses $P$ = parameters of BERT-base, not of the baseline) or the compute $M$ in FLOPs to process an input and a target. We cannot match both at once. The key fact from the slide:

Key factAn encoder-decoder with $L$ layers in the encoder and $L$ in the decoder has about the same number of parameters as a language model with $2L$ layers, whereas the computational cost of both is the same for the given input and task. (The slide leaves "how?" as an exercise. Here it is.)

Derivation (the exercise)

Let one token passing through one layer cost $c$. Suppose the task has an input of $n$ tokens and an output of $m$ tokens.

$$\text{Decoder-only, }L\text{ layers: all }n+m\text{ tokens go through }L\text{ layers}\ \Rightarrow\ M=L\,c\,(n+m),\ \ \text{params}=P_L$$ $$\text{Encoder-decoder, }L+L:\ \ \underbrace{L\,c\,n}_{\text{encoder}}+\underbrace{L\,c\,m}_{\text{decoder}}=L\,c\,(n+m)=M,\ \ \text{params}=2P_L$$ $$\text{Decoder-only, }2L\text{ layers: params}=2P_L\text{ but cost }=2M$$

So the encoder-decoder has the parameters of a $2L$ model but pays the compute of an $L$ model: the encoder only processes the input and the decoder only the output, so each token crosses just $L$ layers. (The extra cross-attention adds only a small cost.) The lecture summary shows the same with attention only: a decoder-only model over $2N$ tokens spends $4LN^2d$ on attention, while the encoder-decoder spends $LN^2d$ on encoder self-attention + $LN^2d$ on decoder self-attention + $LN^2d$ on cross-attention $=3LN^2d$. Feed-forward and projection costs grow with the number of tokens passed through $L$ layers, which is $2N$ in both, so the totals are about equal.

CarefulOn GLUE alone span 2 (83.54) is a hair above span 3 (83.49); all of them are within noise (std about 0.24). The reason to choose 3 is the better average across the non-translation tasks and the shorter targets.

9. Fine-tuning strategies (Module 5)

Fine-tuning all parameters of the model on each task is computationally expensive. The slide looks at two cheaper alternatives and compares them with "all parameters".

9.1 Adapter layers

Add a small adapter layer after the feed-forward block (the figure shows one after the attention sub-layer and one after the FFN) inside every Transformer layer. The adapter is simply dense → ReLU → dense with a narrow inner dimension $d$ and a residual connection. During fine-tuning only the adapter layers and the layer-norm parameters are updated; the rest stays frozen.

Sub-layer output $h$
($d_{\text{model}}$ numbers)

The original $h$ also goes straight to the add step (the residual path).
$$\text{Adapter}(h)=\text{LayerNorm}\big(h+W_{\text{up}}\,\text{ReLU}(W_{\text{down}}h+b_{\text{down}})+b_{\text{up}}\big)$$

Counting the weights (my calculation). $W_{\text{down}}$ is $d\times d_{\text{model}}$ and $W_{\text{up}}$ is $d_{\text{model}}\times d$, so one adapter has $2\,d\,d_{\text{model}}$ weights plus $d+d_{\text{model}}$ biases. With $d_{\text{model}}=768$ and $d=32$: $2\times32\times768=49{,}152$ weights (+800 biases). One BERT-base-sized encoder layer has $4\cdot768^2+2\cdot768\cdot3072=7{,}077{,}888$ weights, so a single $d=32$ adapter is about $0.7\%$ of it. Doubling $d$ doubles the adapter size, so $d$ directly controls the trade-off between parameters trained and accuracy. The slide quotes "typically 0.5 to 8% of the parameters of the transformer layer"; for the largest $d$ values in the table a single adapter would be a larger fraction, so treat the 0.5–8% figure as the slide's rough range.

9.2 Gradual unfreezing

Freeze all layers. Then unfreeze them gradually starting from the top (12th) layer. Unfreezing happens simultaneously for the $k$-th layer of the encoder and of the decoder. With $2^{18}$ fine-tuning steps and 12 layers there are 12 episodes of unfreezing: a new layer is unfrozen every

$$\frac{2^{18}}{12}=\frac{262{,}144}{12}\approx21{,}845\ \text{steps}$$
stepstrainable layers (top = 12)
0 – 21,845L12
21,845 – 43,691L12, L11
……
last 21,845L12 … L1 (all)

Why top first? Top layers hold task-specific features and bottom layers hold general language knowledge; adapting the top first changes the model gently and avoids damaging general knowledge early. (An explanation from the lecture summary, not from the slides.)

10. Multi-task learning and data mixing (Module 6)

10.1 Motivation

So far we pre-trained on C4 and then fine-tuned independently on each task. Adding more good data helps downstream performance, so why not use the datasets of all supervised tasks during pre-training too? In the T5 framework this is easy: all tasks are text-in/text-out, so we simply mix the datasets and train jointly, with no separate loss per task.

C4 (unsupervised denoising)
GLUE, SuperGLUE
CNN/DM, SQuAD
WMT16 EnRo, …
→ sampler →
One T5 model
$2^{19}$ steps of multi-task pre-training, then $2^{18}$ steps of fine-tuning (total budget $2^{19}+2^{18}=786{,}432$ steps)

10.2 Examples-proportional mixing with a cap $K$

Dataset sizes differ enormously (C4 is huge, some GLUE tasks have under a thousand examples). Sampling every example equally would let the biggest dataset drown the rest. Let $e_n$ be the number of examples of task $n$ and $K$ an artificial limit on a dataset's size. The probability of drawing a sample from task $m$ is

$$r_m=\frac{\min(e_m,K)}{\sum_{n}\min(e_n,K)}$$
Why the cap helps (my calculation)Sizes 1,000,000 / 100,000 / 1,000. Without a cap: $r=0.908,\ 0.091,\ 0.0009$ (the huge set takes 91%). With $K=100{,}000$ the sizes become 100,000 / 100,000 / 1,000 (total 201,000), so $r=0.4975,\ 0.4975,\ 0.005$. The huge dataset no longer drowns the others.

10.3 Temperature mixing

Raise the proportions to the power $1/T$ and renormalize (the same trick as softmax temperature):

$$r_m^{(T)}=\frac{(r_m)^{1/T}}{\sum_n (r_n)^{1/T}}$$

Why the limits hold. Write $x^{1/T}=\exp(\ln x/T)$.

  • $T=1$: exponent 1, nothing changes.
  • $T\to\infty$: $\ln x/T\to0$, so every $x^{1/T}\to e^0=1$. All datasets get the same weight, so $r_m\to1/M$: uniform ("for higher $T$ the distribution becomes uniform").
  • $T$ small: the exponent $1/T$ is huge, so the largest $r$ grows much faster than the rest: skewed toward the biggest dataset.

Worked example (my calculation). Three datasets of 1000, 100 and 10 examples (below $K$), so $r=0.901,\ 0.090,\ 0.009$.

10.5 Multi-task pre-training followed by fine-tuning: three variants

1. Multi-task pre-training: mix all datasets (examples-proportional, $K=2^{19}$) for $2^{19}$ steps, then fine-tune on each task for $2^{18}$ steps
2. Leave-one-out pre-training (repeat for every task): pre-train on all tasks except one, then fine-tune on the held-out task. Simulates the real world: a pre-trained model is fine-tuned on a task it had not seen
3. Supervised multi-task pre-training: pre-train on the supervised tasks only, without C4, then fine-tune

11. What if you have 4× more compute? (Module 7)

Four ways to spend a 4× budget:

  1. Bigger model (BERT-base-like → BERT-large-like: more layers, heads, $d_{\text{model}}$, $d_{\text{ff}}$): 2× or 4× size.
  2. Ensemble of 4 separately pre-trained and fine-tuned baselines; aggregate their outputs.
  3. Train longer: 4× the steps ($t=2^{19}\to4t=2^{21}$); the model sees more tokens, still a fraction of the full dataset.
  4. Bigger batch: 128 → 512 sequences for the same $2^{19}$ steps (also more tokens).

  • Making the model 2× bigger while limiting steps to 2× (so it sees fewer tokens than the longer-training case) gives better performance on many tasks: scaling parameters, even at the cost of fewer steps, wins (86.18 on GLUE for 2× size, 2× steps; 85.91 for 4× size).
  • Ensembling also gives reasonable performance, especially on translation (EnDe 28.05, EnRo 28.57; best CNNDM 20.10), but it is weaker on SuperGLUE (71.74) and costs 4× at inference.
  • So which is better, parameters or steps? It is a trade-off. A bigger model needs more compute during fine-tuning and a longer inference time. The best GLUE came from the balanced choice: 2× size and 2× steps.

14. Practice questions

  1. What does zero-shot mean in GPT-2, and what happens to the weights? The task is given in the prompt; the weights do not change ($\Delta\Theta=0$).
  2. Compute the perplexity for token probabilities 0.5, 0.25, 0.1, 0.2. $0.0025^{-1/4}\approx4.47$.
  3. Why are BERT/GPT comparisons unfair? Data, objective, size, training length and fine-tuning all differ at once.
  4. How many tokens does the baseline see and what share of C4? $2^{35}\approx34$B, about 22% of 156B, so under one epoch.
  5. What is the learning rate at step 4×10⁴ and at 10⁶? 0.005 and 0.001.
  6. Show that an L+L encoder-decoder has the cost of an L-layer decoder-only model. Encoder: $Lcn$; decoder: $Lcm$; total $Lc(n+m)$, equal to the decoder-only cost.
  7. What does parameter sharing do? Halves the parameters (2P → P), same cost M, slight loss (GLUE 82.81 vs 83.28).
  8. Why is the span-corruption target short? It holds only sentinels and the missing words: about 104 tokens for a 512-token input.
  9. Which corruption strategy had the best GLUE, and why was it not chosen? Dropping tokens (84.44), but that came from one subtask (CoLA) and it was worse on SuperGLUE; sentinel replacement is overall fine and cheap.
  10. Training loss falls to about 0.1 while GLUE falls to 76.34. Why? The data was repeated 4,096 times ($2^{23}$ unique tokens): memorization.
  11. Unfiltered C4 is 8× bigger. Why is it worse? It has no deduplication or noise filtering, so quality drops on every task.
  12. How many weights are in one adapter with $d_{\text{model}}=768$, $d=32$? $2\times32\times768=49{,}152$ plus 800 biases.
  13. When is a new layer unfrozen in gradual unfreezing? Every $2^{18}/12\approx21{,}845$ steps.
  14. Mix 1000, 100 and 10 examples with T = 2. What are the probabilities? 0.706, 0.223, 0.071.
  15. With 4× compute, what worked best on GLUE? 2× size and 2× steps (86.18), then 4× size (85.91).
  16. How many tokens did T5-11B see? $2048\times512\times2^{20}\approx1.1\times10^{12}$, 32× the baseline.
