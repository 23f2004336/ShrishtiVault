1. Motivation: why not train one model per task?

1.1 The Week 1–2 situation

So far the Transformer was an encoder-decoder machine: text in the source language goes in, translated text comes out. At a higher level it is a black box that takes an input and produces an output. What if we want other NLP tasks?

TaskInputOutput
Sentiment analysisInput textA class: positive / negative / neutral
SummarizationLong documentShort text
Question answeringPassage + questionAnswer
Two problems with training from scratch for each task(1) Slow and data-hungry. A Transformer has millions to billions of randomly initialised parameters; trained from scratch on a small dataset it converges slowly and overfits. (2) Labels are expensive. Labelled data (medical QA, translation for a regional language) is scarce, costly and slow to create. On the other hand, unlabelled text is available in huge amounts on the internet.

So the slides ask: can we use this unlabelled text to train a model? What would the training objective be? And would that help adapt the model to downstream tasks with minimal fine-tuning (zero or a few samples)?

1.2 The lay-person intuition

Ask an ordinary person: "Wow, India has now reached the moon: positive or negative?", or "Did the lander use AI for soft landing?" after reading an excerpt, or "Are these meaningful sentences: 'He likes to stay / stray / sway'?". They will answer all of them, even though they were never trained on those exact tasks. Why? Over a lifetime of listening and reading, they built a strong understanding of language without explicit supervision.

The idea of the weekCan a model develop a basic understanding of language by being exposed to a large amount of raw text? [Pre-training] And after that, can it do well on downstream tasks with minimum supervision? [Supervised fine-tuning]

1.3 The two-stage recipe

Stage 1: Pre-training (language modelling)
Huge raw, unlabelled text (Wikipedia, web, books) → next-word prediction → base model with parameters $\hat\theta$
↓ initialise from $\hat\theta$
Stage 2: Supervised fine-tuning (downstream tasks)
Small labelled dataset (text, label) → small change to the architecture → task-adapted model (sentiment, entailment, multiple choice, ...)
Learn language once, adapt many times

The slide's evidence: with this representation, a simple linear model classifies reviews with 91.8% accuracy, beating the state of the art at the time, and the approach matches earlier supervised systems using 30 to 100 times fewer labelled examples.

2. What is a language model?

2.1 Setup

Let $V$ be the vocabulary: the collection of all unique tokens (words or sub-words). A text is a sequence $X=(x_1,x_2,\dots,x_T)$ with each $x_i\in V$. Example: if $V=\{\text{an, apple, ate, I}\}$ then some possible sequences (not all grammatical) are:

  1. an apple ate I
  2. I ate an apple
  3. I ate apple
  4. an apple

Intuitively, some are more probable than others. By "probable" we mean: given a very large corpus, some sequences would appear more often. A language model is a function that takes a sequence and assigns it a probability:

$$f:(x_1,\dots,x_T)\ \longrightarrow\ [0,1]$$

(Here "I ate an apple" should get a larger value than "an apple ate I".)

2.2 Why we cannot model the joint probability directly

The most direct way is a table with one probability per possible sequence. But the number of sequences of length $T$ is $|V|^T$. For our toy vocabulary and $T=4$ that is $4^4=256$, but for a real vocabulary $|V|=40{,}478$ even $T=2$ gives $40478^2\approx1.6\times10^9$ entries, and $T=512$ is astronomically large. We can neither store nor estimate such a table. We need a smarter factorisation.

2.3 The chain rule of probability

From the product rule $P(A,B)=P(A)\,P(B\mid A)$, applying it repeatedly gives (derivation step by step):

$$P(x_1,x_2)=P(x_1)P(x_2\mid x_1)$$ $$P(x_1,x_2,x_3)=P(x_1,x_2)\,P(x_3\mid x_1,x_2)=P(x_1)P(x_2\mid x_1)P(x_3\mid x_1,x_2)$$ $$\boxed{P(x_1,\dots,x_T)=\prod_{i=1}^{T}P(x_i\mid x_1,\dots,x_{i-1})}$$

This is exact, not an approximation. It turns one impossible job (a probability for each whole sequence) into $T$ smaller jobs: predict each word given the words before it.

2.4 Worked example (created for practice)

Sentence "I ate an apple". Suppose a model gives: $P(\text{I})=0.3$, $P(\text{ate}\mid\text{I})=0.2$, $P(\text{an}\mid\text{I ate})=0.5$, $P(\text{apple}\mid\text{I ate an})=0.4$. Then $P(\text{I ate an apple})=0.3\times0.2\times0.5\times0.4=0.012$. A bad word order such as "an apple ate I" would get much smaller conditionals (for instance $P(\text{ate}\mid\text{an apple})$ is small), and so a smaller product.

2.5 The naive independence assumption and why it fails

The simplest assumption is that words are independent: $P(x_1,\dots,x_T)=\prod_iP(x_i)$. Then the order would not matter at all. But words depend on what came before:

(a) I enjoyed reading a book    (b) I enjoyed reading a thermometer

The presence of "enjoyed reading a" makes "book" far more likely than "thermometer". Under independence both would just have their general word frequencies. So we keep the conditionals $P(x_i\mid x_1..x_{i-1})$: the current word depends on all previous words.

2.6 How do we estimate the conditionals?

Counting is hopeless for long contexts, so we use an autoregressive model: a parameterised function with a fixed number of parameters $\theta$ that outputs the conditional distribution. Written as:

$$P(x_i\mid x_1,\dots,x_{i-1})=f_\theta(x_i\mid x_1,\dots,x_{i-1})$$

Can $f_\theta$ be a Transformer? Yes: it takes $x_1..x_{i-1}$ and outputs a distribution over $V$ for $x_i$. This task is called causal language modelling (CLM): "causal" because each prediction depends only on the past.

3. Labels for free: self-supervised learning

Normally supervised learning needs (input, label) pairs made by humans. Next-word prediction creates them automatically from raw text:

  1. Take any document (Wikipedia, news, books) and split it into tokens $x_1..x_T$.
  2. For each position $k$, the prefix $(x_1..x_k)$ is the input and the next token $x_{k+1}$ is the label.

5. Causal language modelling with a decoder-only Transformer

5.1 What changes from the Week 2 decoder

The Week 2 decoder had three sub-layers: masked self-attention, cross-attention to the encoder, and FFN. With no encoder there is nothing to cross-attend to, so the decoder-only block keeps only:

Feed Forward Network (+ Add & LayerNorm)
↑
Masked Multi-Head Self-Attention (+ Add & LayerNorm)
↑
Token embeddings + positional embeddings
One decoder-only block (cross-attention removed)

The input is the sequence, starting with a ⟨go⟩ token: $\langle go\rangle,x_1,x_2,x_3$. The output at each position is a probability distribution over the vocabulary.

5.2 The causal mask

We want the model to see only the present and past inputs. We add the mask matrix $M$ to the scaled scores before the softmax (same as Week 2):

$$M_{t,j}=\begin{cases}0&j\le t\\-\infty&j>t\end{cases}\qquad A_{masked}=\text{softmax}\!\Big(\frac{QK^T}{\sqrt{d_k}}+M\Big)V$$
⟨go⟩x1x2x3
⟨go⟩0−∞−∞−∞
x100−∞−∞
x2000−∞
x30000

Why exactly zero weight? For a future position $j>t$:

$$\alpha_{t,j}=\frac{\exp(e_{t,j}+M_{t,j})}{\sum_{m}\exp(e_{t,m}+M_{t,m})}=\frac{\exp(-\infty)}{\text{Sum}}=\frac{0}{\text{Sum}}=0$$

The denominator contains only the allowed positions, so the remaining weights still add up to 1. Worked example (created for practice): the row of scores for position 2 is $(1,2,3)$. Masked, it becomes $(1,2,-\infty)$, $\exp\to(2.718,\ 7.389,\ 0)$, sum 10.107, weights $\approx(0.269,\ 0.731,\ 0)$. The future word is ignored.

5.3 Every output is one factor of the chain rule

This is the neat part. Feed $\langle go\rangle,x_1,x_2,x_3$ in one pass. Because of the mask, output $i$ depends only on earlier inputs. So:

Input at position⟨go⟩x1x2x3
Output (prediction)$p(x_1)$$p(x_2\mid x_1)$$p(x_3\mid x_2,x_1)$$p(x_4\mid x_3,x_2,x_1)$
The four outputs are the four terms of the chain rule
$$P(x_1,..,x_4)=P(x_1;\theta)\,P(x_2\mid x_1;\theta)\,P(x_3\mid x_2,x_1;\theta)\,P(x_4\mid x_3,x_2,x_1;\theta)$$

The only difference from the abstract chain rule: now each probability is determined by the model parameters $\theta$. The objective is to maximise the likelihood $L(\theta)$ of the training text. A single pass computes all $T$ terms at once (parallel), which is why training is fast.

6. The training objective: likelihood, log-likelihood, cross-entropy

6.1 From likelihood to loss (step by step)

  1. Likelihood of the data under the model: $L(\theta)=\prod_{i=1}^{T}P(x_i\mid x_1..x_{i-1};\theta)$. Larger is better.
  2. A product of many numbers below 1 underflows to nearly 0 and is awkward to optimise. Take the log (it is monotonic, so the maximiser does not change): $\log L=\sum_i\log P(x_i\mid x_{
  3. Optimisers minimise, so flip the sign, and average over tokens:
$$\mathcal L_{pre}(\theta)=-\frac1T\sum_{t=1}^{T}\log P_\theta(x_t\mid x_1,\dots,x_{t-1})$$

This is the negative log-likelihood. (The slide writes the sum without the $\frac1T$, as $\sum\log P$ to be maximised.)

6.2 It is the cross-entropy loss

At position $i$ the model outputs $\hat y_i=\text{softmax}(h^n[i]W_v)$, a distribution over $|V|$ words, and the true word is a one-hot vector $y_i$ (a 1 at the correct word, 0 elsewhere). Then

$$-\sum_{v\in V}y_{i,v}\log\hat y_{i,v}=-\log\hat y_{i,x_i}$$

because every term except the correct word's is multiplied by 0. So "cross-entropy with a one-hot target" = "minus log-probability of the correct next word". The slide's loss $L=-\sum_{x\in\mathcal X}\sum_{i=1}^{T}y_i\log\hat y_i$ is this, summed over all sequences.

6.3 Worked example (created for practice)

Use the probabilities from section 2.4 for "I ate an apple": $-\ln0.3=1.204$, $-\ln0.2=1.609$, $-\ln0.5=0.693$, $-\ln0.4=0.916$. Sum $=4.423=-\ln0.012$ ✓. Average loss $=4.423/4\approx1.106$.

Perplexity (a common way to read the loss)$\text{PPL}=e^{\mathcal L}$. Here $e^{1.106}\approx3.02$: the model is, on average, as unsure as if it were choosing between about 3 equally likely words at each step. Lower is better; a perfect model has perplexity 1.

6.4 Teacher forcing in language modelling

During training the input at each position is the true previous word from the text (not the model's own guess), exactly as in Week 2. The slide says this is used "instead of auto-regressive training for quicker and stable convergence": all positions are processed in parallel in one forward pass. Only at generation time (section 11) is the model run one token at a time.

7.3 Training data: BookCorpus

  • About 7,000 unique books, 74 million sentences, roughly 1 billion words, across 16 genres.
  • Uses long-range contiguous text: sentences and paragraphs are not shuffled, so the model can learn long-distance dependencies. (The "1B words" benchmark has shuffled sentences with no contiguity, so it is less suitable.)

Inside masked multi-head attention (slide): for each head, $Q,K,V$ → MatMul $Q^TK$ + mask $M$ → scale by $1/\sqrt{d_k}$ → softmax → dropout → MatMul with $V$; the 12 head outputs are concatenated, passed through a linear layer ($W^O$), then dropout, residual add and layer norm.

GELU and dropoutGELU: $\text{GELU}(x)=x\,\Phi(x)$ where $\Phi$ is the standard normal CDF. Unlike ReLU's hard cut at 0 it is smooth: GELU(1)=0.841, GELU(0)=0, GELU(−1)=−0.159. Dropout randomly sets a fraction of activations to 0 during training so the network cannot rely on any one unit, reducing overfitting.

7.5 Learned positional embeddings

The original Transformer used fixed sinusoidal positions (Week 2). GPT-1 instead uses a learned table $W_p\in\mathbb R^{512\times768}$: row $p$ is the vector for position $p$, trained along with everything else. Trade-off from Week 2: simple and flexible, but it cannot represent positions beyond 512.

9. Pre-training in practice

  • Input shape: $(B,T,C)=(64,512,768)$: batch of 64 sequences, 512 tokens each, 768-dim embeddings.
  • Loss: cross-entropy $L=-\sum\sum y_i\log\hat y_i$ (section 6).
  • Optimizer: Adam with a cosine learning-rate schedule (the lecture summary says AdamW, which is Adam with decoupled weight decay: weights shrink slightly each step, separately from the gradient).
  • Strategy: teacher forcing, so every position is trained in parallel.
$$\eta_t=\eta_{min}+\tfrac12(\eta_{max}-\eta_{min})\Big(1+\cos\frac{\pi t}{T_{total}}\Big)$$

The learning rate starts at $\eta_{max}$ and falls smoothly along a half cosine to $\eta_{min}$: big steps early, careful small steps near the end. (Formula is the standard cosine schedule; the slides only name it.)

10. Supervised fine-tuning

10.1 Idea

Fine-tuning adapts the pre-trained model to a downstream task with minimal change to the architecture. Each labelled sample is a sequence $x_1..x_m$ with a label $y$.

  1. Initialise all parameters from the pre-trained model.
  2. Input side: add special tokens depending on the task, such as a start token ⟨s⟩ and end token ⟨e⟩ (and a delimiter ⟨$⟩ when there are two pieces of text).
  3. Output side: remove the language-model head and attach a classification head, a single linear layer $W_y$ (randomly initialised).
  4. Train on the labelled data (all weights, plus the new head, are updated).
ŷ = softmax(Wy h12m)
↑ last position's output
Pre-trained 12 blocks (initialised from pre-training)
↑
⟨s⟩ x1 x2 … xm ⟨e⟩
Fine-tuning for classification

10.2 Why use the last position?

Because of the causal mask, a position can see only itself and earlier positions. So the last position is the only one that has seen the entire input; it is the natural summary of the sequence. The first positions have seen almost nothing.

10.3 The classification head and loss

$$\hat y=P(y\mid x_1,..,x_m)=\text{softmax}\big(W_y\,h_l^{m}\big),\quad W_y\in\mathbb R^{d\times C}\ (768\times C)\qquad \mathcal L_{FT}=-\sum_{(x,y)}\log\hat y_{y}$$

The lecture summary adds a bias, $\text{softmax}(h_l^mW_y+b_y)$; same idea. For $C=2$ classes the new head has only $768\times2=1536$ weights (+2 bias), tiny compared with the 116M already learned. Samples shorter than the context length are padded, longer ones truncated.

Worked example (created for practice): logits for (positive, negative) $=(1.2,-0.4)$. $e^{1.2}=3.320$, $e^{-0.4}=0.670$, sum 3.990, so $P=(0.832,\ 0.168)$. If the true class is positive, loss $=-\ln0.832=0.184$; if negative, $-\ln0.168=1.784$.

11. Text generation and decoding strategies

11.1 The autoregressive loop

For generation we use the model exactly as in the chain rule: predict the next word, append it, repeat. Prompt: "I like". Feed ⟨s⟩ I like, with the causal mask; sample a next token ("to"); append; run again ("think"); and so on.

⟨s⟩ I like

⟨s⟩ I like to think
→ model →
that
Output: "I like to think that" (stop at length 5 or when the model outputs ⟨e⟩)

Stopping criteria (slide): reach a maximum sequence length (here 5), or the model outputs the end token ⟨e⟩. In the mask on the slide the prompt tokens (⟨s⟩, I, like) are all visible to each other, and each new position can see everything before it.

11.2 Pure argmax is not enough

The model gives a probability for each possible next word. The simplest rule is greedy decoding: always take the most probable word. Two questions from the slide: does the same prompt always give the same output? With greedy, yes; the model is deterministic. Or will it be creative? Not with greedy.

Wishlist for text generation (slide)(1) Discourage degenerate text: repeated or incoherent, such as "I like to think that I like to think ..." or "I like to think that reference know how to think best selling book". (2) Encourage creativity: different, sensible continuations for the same prompt ("I like to read a book", "I like to buy a hot beverage", "I like a person who cares about others"). (3) Accelerate generation of tokens.

To get diversity we sample from the distribution instead of always taking the maximum, and we control the shape of that distribution with the strategies below.

11.3 Temperature

The linear head produces raw scores (logits) $u_{t+1}\in\mathbb R^{|V|}$. Temperature $\tau>0$ divides them before the softmax:

$$P(x_{t+1}=v\mid x_{\le t})=\frac{\exp(u_{t+1,v}/\tau)}{\sum_{w=1}^{|V|}\exp(u_{t+1,w}/\tau)}$$
  • $\tau=1$: the model's normal distribution.
  • $\tau\to0$: dividing by a tiny number blows up the gaps between logits, so the largest takes essentially all the probability: this becomes greedy / argmax, deterministic.
  • $\tau>1$: gaps shrink, the distribution flattens, more random and "creative" (but more chance of nonsense).
  • $\tau\to\infty$: uniform distribution over all words.

Worked example (created for practice): logits $(2,1,0)$ for tokens A, B, C.

11.4 Top-k sampling

Keep only the $k$ most probable tokens, set the others to 0, renormalise so the kept ones sum to 1, then sample. This removes the long tail of silly low-probability words. Example (created for practice): probabilities $(0.40,0.25,0.15,0.10,0.06,0.04)$, $k=3$: keep 0.40, 0.25, 0.15 (sum 0.80) → renormalised $(0.500,\ 0.3125,\ 0.1875)$.

11.5 Top-p (nucleus) sampling

Choose the smallest set of top tokens whose cumulative probability reaches $p$ (e.g. 0.9), renormalise, and sample. The set size adapts: if the model is confident, few tokens are kept; if it is unsure, many. Same example with $p=0.9$: cumulative sums $0.40,\ 0.65,\ 0.80,\ 0.90$ → the first 4 tokens are kept (sum 0.90) → renormalised $(0.444,\ 0.278,\ 0.167,\ 0.111)$.
