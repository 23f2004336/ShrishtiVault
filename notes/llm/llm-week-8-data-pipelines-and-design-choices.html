1. Why scale the data? (L40)

1.1 Where we stand

Datasets seen so far in the course:

ModelDatasetSize

T5 (10B params)C4~175 billion tokens

The lecture asks: do we need even more data? If yes, where do we get it, and what must we worry about (duplicates, toxicity, bias)?

Two reasons to scale the data:

  1. T5 overfits when data is repeated for many epochs. If you only have a small dataset, you must loop over it, and the model starts memorizing. Fresh data avoids this.
  2. Scaling laws (a paper that came a few months after T5) say the loss keeps falling when data grows, but only if the model is big enough to use it.

1.2 The scaling law formula

Let $N$ be the number of non-embedding parameters and $D$ the number of training tokens. The test loss is

$$L(N,D)=\left[\left(\frac{N_c}{N}\right)^{\alpha_N/\alpha_D}+\frac{D_c}{D}\right]^{\alpha_D}$$

with $N_c=8.8\times10^{13}$ (88 trillion parameters), $D_c=5.4\times10^{13}$ (54 trillion tokens), $\alpha_N=0.076$ and $\alpha_D=0.095$. So $\alpha_N/\alpha_D=0.8$.

How to read it in plain words The bracket has two terms. The model term $(N_c/N)^{0.8}$ gets smaller as the model grows. The data term $D_c/D$ gets smaller as the data grows. The whole bracket is then raised to the small power 0.095, which squeezes everything and makes the loss move slowly. Loss is high when either term is big, so you need both to be small.

1.3 Worked example from the slide: N = 100M, D = 10M

Step 1, model term. $N_c/N = 8.8\times10^{13}/10^{8}=8.8\times10^{5}$. Raise to 0.8 using logarithms:

$$\ln(8.8\times10^{5})=\ln 8.8+5\ln 10=2.175+11.513=13.688$$ $$0.8\times13.688=10.950,\qquad e^{10.950}\approx 56{,}962$$

Step 2, data term. $D_c/D=5.4\times10^{13}/10^{7}=5.4\times10^{6}=5{,}400{,}000$.

Step 3, add and apply the outer power.

$$5{,}400{,}000+56{,}962=5{,}456{,}962,\quad \ln=15.512,\quad 0.095\times15.512=1.4736,\quad e^{1.4736}\approx 4.365$$

The slide shows 4.36 (it cuts the last digit; exact rounding gives 4.37). The training loss can go to zero because the model memorizes 10M tokens, but the test loss is what the law predicts. Here the data term (5.4 million) is about 100 times bigger than the model term (56,962), so data is the bottleneck.

1.4 What happens when we add data? (derivation of the limits)

Data to infinity. $D\to\infty$ makes $D_c/D\to0$, so

$$L\to\left[\left(\tfrac{N_c}{N}\right)^{\alpha_N/\alpha_D}\right]^{\alpha_D}=\left(\tfrac{N_c}{N}\right)^{\alpha_N}\quad\text{(the model floor)}$$

(we multiplied the exponents: $\frac{\alpha_N}{\alpha_D}\cdot\alpha_D=\alpha_N$). For $N=100$M: $(8.8\times10^5)^{0.076}=e^{0.076\times13.688}=e^{1.040}\approx2.83$.

Model to infinity. $N\to\infty$ makes the model term $\to0$, so $L\to(D_c/D)^{\alpha_D}$ (the data floor). For $D=10$M this is $(5.4\times10^6)^{0.095}=e^{0.095\times15.502}\approx4.36$. That is exactly why the loss in the table below stays at 4.36 for every model size when $D=10$M.

2.3 Position encoding

Self-attention has no sense of order, so we must tell it where each token is.

  • Absolute (sinusoidal): add a fixed vector: $PE_{(pos,2i)}=\sin\!\big(pos/10000^{2i/d}\big)$, $PE_{(pos,2i+1)}=\cos\!\big(pos/10000^{2i/d}\big)$.
  • Absolute (learned): a trainable table with one vector per position (GPT-1, GPT-3).
  • Relative: the score depends on the distance $i-j$, not on the positions themselves.
  • RoPE: rotate queries and keys. Used by PaLM, LLaMA. Derived below.
  • ALiBi: subtract a distance penalty from the score. Derived below.
  • NoPE: no explicit encoding. The causal mask alone lets the model learn order.

RoPE derivation (extra, to understand why it is "relative")

Take a 2-dimensional query $q$ and key $k$ at positions $m$ and $n$. Rotate each by an angle proportional to its position, $\theta$ being a fixed frequency:

$$\tilde q_m=R(m\theta)\,q,\qquad \tilde k_n=R(n\theta)\,k,\qquad R(\phi)=\begin{pmatrix}\cos\phi&-\sin\phi\\ \sin\phi&\cos\phi\end{pmatrix}$$

The attention score is the dot product. Use $R(a)^{T}=R(-a)$ and $R(a)R(b)=R(a+b)$:

$$\tilde q_m^{T}\tilde k_n=q^{T}R(m\theta)^{T}R(n\theta)\,k=q^{T}R\big((n-m)\theta\big)\,k$$

The score depends only on $n-m$, the distance, even though we rotated by absolute positions. For a $d$-dimensional vector, split it into $d/2$ pairs and rotate pair $i$ with its own frequency $\theta_i=10000^{-2i/d}$ (the same idea as the sinusoidal encoding). RoPE is applied to $q$ and $k$ only, not to $v$.

ALiBi

No change to the inputs. Instead the score between token $i$ (query) and an earlier token $j$ becomes

$$\text{score}_{ij}=\frac{q_i\cdot k_j}{\sqrt{d_k}}-m_h\,(i-j)$$

where $m_h$ is a fixed slope per head (different heads get different slopes, a geometric sequence). Far tokens get a bigger penalty, so nearby words matter more. Because the rule is a plain subtraction, it also works for sequences longer than those seen in training.

2.4 Attention variants

MHA: each of $h$ heads has its own $Q,K,V$. MQA: all heads share one $K$ and one $V$. GQA: heads are split into $g$ groups, each group shares one $K,V$ (in between).

Why MQA and GQA help: the KV cache (derivation)

While generating text, the model keeps the keys and values of all earlier tokens so it does not recompute them. For one token, one layer, one K/V head of size $d_h$: we store $K$ and $V$, so $2d_h$ numbers. Over $L$ layers and $h_{kv}$ K/V heads:

$$\text{cache per token}=2\cdot L\cdot h_{kv}\cdot d_h\ \text{values}$$

GPT-3 numbers: $L=96$, $h=96$, $d_h=12288/96=128$.

Sparse attention

Full attention costs $n^2$ score computations. If each token only looks at a window of $w$ tokens, the cost is about $n\cdot w$. For $n=2048$, $w=256$: $4.19$M against $0.52$M, which is 8 times cheaper. GPT-3 alternates dense layers with locally banded sparse layers.

FlashAttention (same answer, less memory traffic)

Standard attention writes the $n\times n$ score matrix to slow GPU memory. FlashAttention computes it in small tiles in fast on-chip memory and never stores the full matrix. The trick is an online softmax. A softmax needs the max $m$ and the sum $\ell=\sum e^{s-m}$. When a new block arrives with block max $m_b$ and block sum $\ell_b$:

$$m_{new}=\max(m,m_b),\qquad \ell_{new}=\ell\,e^{\,m-m_{new}}+\ell_b\,e^{\,m_b-m_{new}}$$

This rescales the old sum to the new max, so the result is exactly the normal softmax. Check with scores $[1,3,2,4]$ split in blocks $[1,3]$ and $[2,4]$:

  • Block 1: $m=3$, $\ell=e^{-2}+1=1.135$.
  • Block 2: $m_b=4$, $\ell_b=e^{-2}+1=1.135$. $m_{new}=4$, $\ell_{new}=1.135e^{3-4}+1.135e^{4-4}=0.418+1.135=1.553$.
  • Direct: $e^{-3}+e^{-1}+e^{-2}+1=0.050+0.368+0.135+1=1.553$. Same.

PagedAttention stores the KV cache in fixed-size blocks, like pages in an operating system, so serving wastes very little memory to fragmentation.

2.5 Normalization

LayerNorm for a vector $x$ of size $d$: $\mu=\frac1d\sum x_i$, $\sigma^2=\frac1d\sum(x_i-\mu)^2$, output $\gamma\odot\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta$.

RMSNorm drops the mean: output $\gamma\odot\frac{x}{\sqrt{\frac1d\sum x_i^2+\epsilon}}$. It saves the mean computation and the bias $\beta$.

Example with $x=[1,2,3,4]$: $\mu=2.5$, $\sigma=1.118$, so LayerNorm gives $[-1.34,-0.45,0.45,1.34]$. RMSNorm: mean of squares $=7.5$, RMS $=2.739$, gives $[0.37,0.73,1.10,1.46]$. Same idea (rescale), RMSNorm is a bit cheaper and works about as well.

DeepNorm scales the residual branch by a constant so very deep stacks (hundreds of layers) train stably.

2.6 Activation and feed-forward

  • ReLU $=\max(0,x)$. GeLU $\approx x\,\Phi(x)$ (smooth, $\Phi$ is the normal CDF). Swish $=x\,\sigma(x)$.
  • Gated units (GLU family). Use two projections, one is a gate: $\text{SwiGLU}(x)=\text{Swish}(xW)\odot(xV)$, and GeGLU replaces Swish with GeLU. PaLM uses SwiGLU.

Why SwiGLU hidden size is 8d/3 in many models (extra)

A normal FFN has two matrices, $d\to4d\to d$: $2\cdot d\cdot4d=8d^2$ parameters. A gated FFN has three matrices ($W$, $V$ and the output). To keep the same budget with hidden size $h$: $3dh=8d^2\Rightarrow h=\tfrac83 d$. (PaLM instead keeps $h=4d$ and accepts more parameters.)

Replace the one FFN with $E$ expert FFNs and a router. Each token goes to its top $k$. Total parameters grow about $E$ times, but compute per token only grows $k$ times. Example: $E=64$ experts, $k=2$: 64 times the FFN parameters but only $2/64\approx3\%$ of them run for a token. This is how GShard (1.1T) and Switch (1.6T) are so large.

2.7 Objective and optimizer

Objectives: CLM (predict next token), MLM (fill masked tokens), Denoising (rebuild corrupted text). GPT-1, GPT-3 and PaLM all use CLM.

Adam keeps a running mean of the gradient and of its square:

$$m_t=\beta_1m_{t-1}+(1-\beta_1)g_t,\quad v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2,\quad \theta_t=\theta_{t-1}-\eta\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}$$

AdamW applies weight decay directly to the weights, $\theta\leftarrow\theta-\eta\lambda\theta$, instead of adding $\lambda\theta$ to the gradient. If it were in the gradient, it would also be divided by $\sqrt{v}$, so parameters with big gradients would be decayed less. Decoupling fixes that.

Adafactor saves memory. Adam stores $v$ for every weight. For an $n\times m$ matrix, Adafactor stores only row sums and column sums of $v$ and rebuilds $v_{ij}\approx R_iC_j/\sum R$. Memory goes from $nm$ to $n+m$. For a $18{,}432\times73{,}728$ matrix (PaLM FFN): 1.36 billion numbers against about 92 thousand.

LION uses only the sign of a momentum: $\theta\leftarrow\theta-\eta\,(\text{sign}(\beta_1m+(1-\beta_1)g)+\lambda\theta)$. It keeps one state per weight instead of two.

3. Sourcing and cleaning the data (L43, L44)

3.1 Where the text comes from

Almost every pre-training dataset was built by crawling the web. The web holds more than 100 petabytes. You can write your own HTML scraper, or use Common Crawl (CC). CC releases a snapshot every month with about 3 to 5 billion pages. Raw pages contain duplicates, toxic text, low-quality text and personal data. The old rule applies: garbage in, garbage out (GIGO). So we clean first.

Many companies do not publish their pipeline. For example, DeepMind's MassiveWeb (used for Gopher) uses a custom HTML scraper and Google's SafeSearch signal. The pipelines with public details are: C4 (2019), The Pile (2020), Falcon/RefinedWeb (2023), ROOTS (2023), RedPajama v1/v2 (2023), DOLMA (2024) and Sangraha (2024).

  • Language ID. A classifier gives each page a language and a confidence. Keep pages above a threshold (C4 kept English with probability at least 0.99, from the summary).
  • Toxicity. Simple heuristics (bad-word lists), or a model such as Perspective API. Hate speech and stereotypes are harder than swear words.
  • Quality. Either rules (lines end with punctuation, enough words per line) or a language model trained on trusted text. For a text of $n$ tokens the model's perplexity is $\exp\!\big(-\tfrac1n\sum_i\log p(w_i)\big)$. Low perplexity means "looks like the trusted text", so keep it.
  • PII. Regular expressions find emails, phone numbers, IP addresses and the like, and mask them. Example pattern for email: [\w.+-]+@[\w-]+\.[\w.]+ (extra).

3.4 Deduplication in detail

Two kinds of duplicates:

  • Exact: the same text appears on two pages ("The orbit of Aditya-L1 spacecraft is a periodic Halo orbit" on webpage 1 and webpage 2). Algorithm: suffix array.
  • Fuzzy (near): almost the same text. Webpage 1: "...Halo orbit which is located roughly 1.5 million km from earth..." and webpage 2: "...Halo orbit. The orbit is located roughly 1.5 million km from earth...". Algorithms: MinHash, SimHash, Locality Sensitive Hashing (LSH).

MinHash: derivation

Step 1, turn a document into a set. Cut it into shingles (small word pieces). Similarity of two sets is the Jaccard index

$$J(A,B)=\frac{|A\cap B|}{|A\cup B|}$$
A = {1,2,3,4}
B = {2,3,4,5}
A ∩ B = {2,3,4} → 3
A ∪ B = {1,2,3,4,5} → 5
Jaccard = 3/5 = 0.6

Step 2, avoid comparing big sets. Take a random hash function $h$ (a random ordering of all possible shingles). Define $\text{minhash}_h(A)=\min_{x\in A}h(x)$.

Key fact: $P[\text{minhash}(A)=\text{minhash}(B)]=J(A,B)$ Look at the union $A\cup B$. Under a random hash, the element of the union with the smallest hash value is equally likely to be any element of the union. The two minhashes are equal exactly when that smallest element lies in both sets, i.e. in $A\cap B$. So the probability is $|A\cap B|/|A\cup B|=J$.

Step 3, use many hashes. Use $k$ hash functions. The fraction of hashes where the minimums agree estimates $J$. The list of $k$ minimums is the document's signature, tiny compared with the document. Toy run with 8 hash functions on the sets above:

LSH: derivation of the S-curve

Even with short signatures, comparing every pair of documents is too slow for billions of pages. LSH uses a trick: split the signature of $k=b\cdot r$ numbers into $b$ bands of $r$ rows. Two documents become a candidate pair if they match in all $r$ rows of at least one band. Let the Jaccard similarity be $s$:

$$P(\text{one row matches})=s,\quad P(\text{a band matches})=s^{r},\quad P(\text{a band fails})=1-s^{r}$$ $$P(\text{all }b\text{ bands fail})=(1-s^{r})^{b}\;\Rightarrow\; P(\text{candidate})=1-(1-s^{r})^{b}$$

This is an S-shaped curve with a sharp jump near $s\approx(1/b)^{1/r}$. For $b=20,r=5$: $(1/20)^{1/5}=0.55$.

Pairs with $s=0.8$ are almost always caught (1.000) while pairs with $s=0.2$ almost never are (0.006). So we only compare documents that fall in the same bucket, and we can tune $b$ and $r$ to set the similarity at which two pages count as duplicates.

SimHash (mentioned on the slide) is another fuzzy method: it turns a document into one short bit string such that similar documents differ in only a few bits.

Which order? Most duplicates in CC are exact duplicates (slide). The Pile uses fuzzy dedup instead of exact. The recommendation: run fuzzy dedup first, then exact dedup, to catch both kinds.

5.2 What duplicates do

Duplicate text in the corpus
→
Model memorizes it
→
Test text may be inside training data
→
Privacy leaks
(emails, addresses can be extracted)
  • Memorization. The model reproduces training text.
  • Wrong test picture. If test text is also in training, scores look better than real ability.
  • Privacy risk. Repeated personal data is easy to extract.

5.3 The numbers on the slides

  • For a 1B model a hundred duplicates are harmful. At 175B even a few duplicates can have a disproportionate effect.
  • In the C4 histogram of exact duplicates of 400-character sequences, millions of sequences repeat at least 10 times.
  • A sequence present 10 times in training is generated on average 1000 times more often than a sequence present once. (Ten times the data gives a thousand times the output, so memorization grows much faster than the count.)
  • "Learning from Repeated Data": an 800M model can fall to the level of a model 2 times smaller (400M) by repeating just 0.1% of the data 100 times, even though the other 90% of tokens stay unique. (The lecture summary says 1B and 400M. The slide says 800M, use that.)
Two cautions (slide 38)
  • The Pythia models found that deduplicating The Pile had only a limited effect on zero-shot scores. So dedup is not magic for every benchmark.
  • Gopher did not use a quality classifier trained on a "gold" set such as Wikipedia or Reddit-linked pages, because it could bias against some demographics and erase dialects. "A high-quality Reddit post does not look like a high-quality academic paper; and even peer review has high variance" (A Pretrainer's Guide). So all pipelines are leaky.

6.4 Data mixing

Suppose we train for 15 million steps, each step with $2^{16}=65{,}536$ tokens:

$$15\times10^{6}\times65{,}536\approx9.83\times10^{11}\approx1\text{ trillion tokens}$$

At each step we draw those $2^{16}$ tokens from the sources following a fixed distribution (the mixing weights). Slide example: C4 40%, OpenWebText 15%, Books 10%, RealNews 10%, Code 10%, Wikipedia 10%, Stories 5%.

Mixing weights: slide example and three real models

Epochs per source (derivation)

If source $m$ has weight $w_m$, total training tokens are $T_{tot}$ and the source has $S_m$ tokens, then

$$\text{tokens drawn from }m=w_m\,T_{tot},\qquad \text{epochs}_m=\frac{w_m\,T_{tot}}{S_m}$$

6.5 Temperature sampling for mixing (extra, from the summary)

Many multilingual or multi-source models set the share of source $m$ by size $E_m$ with a temperature $T$:

$$P_m(T)=\frac{\big(\min(E_m,K)\big)^{1/T}}{\sum_{j}\big(\min(E_j,K)\big)^{1/T}}$$

$K$ is a cap so no source counts for more than $K$ tokens. Derivation of what $T$ does, ignoring the cap: write $E^{1/T}=e^{\ln E/T}$.

  • $T=1$: $P_m=E_m/\sum E$. Shares are proportional to size.
  • $T\to\infty$: $\ln E/T\to0$, so every term $\to e^0=1$ and $P_m\to1/M$ for $M$ sources. All sources equal.
  • $T<1$: the exponent $1/T>1$ stretches differences, so the biggest source takes even more.

Example with the DOLMA source sizes (to show the effect, not how DOLMA was built). For $T=2$ take square roots: 47.8, 20.3, 14.1, 9.4, 8.4, 2.4, 2.1 (sum 104.5), then divide.

8. Practice questions

  1. N = 100M, D = 10M. What is the loss and which term dominates?
    About 4.36. Data term $5.4\times10^6$ is far bigger than the model term 56,962, so data is the bottleneck.
  2. What does $L$ approach as $D\to\infty$? Give the value for N = 100M.
    $(N_c/N)^{\alpha_N}\approx2.83$ (the model floor).
  3. Why do models with different sizes give the same loss at D = 10M?
    The data term $(D_c/D)^{\alpha_D}$ alone is 4.36 and the model term is tiny compared with it.
  4. Name the five pipeline jobs.
    Language ID, deduplication, toxicity filtering, quality filtering, PII removal.
  5. Prove that $P[\text{minhash}(A)=\text{minhash}(B)]=J(A,B)$.
    The smallest hash in $A\cup B$ is equally likely to be any element of the union. The minhashes match iff it lies in $A\cap B$. Probability $|A\cap B|/|A\cup B|$.
  6. With b = 20 bands of r = 5 rows, what is the chance two documents with J = 0.8 are compared?
    $1-(1-0.8^5)^{20}=1-(0.672)^{20}\approx1.000$.
  7. Why does MQA save memory at inference?
    All heads share one K and V, so the KV cache is $h$ times smaller (96 times for GPT-3).
  8. Why is RoPE a relative encoding?
    Rotating $q$ by $m\theta$ and $k$ by $n\theta$ gives a dot product that depends on $(n-m)\theta$ only.
  9. What fraction of Common Crawl survives RefinedWeb, and which step removes the most?
    11.67%. Language identification removes the most (about 50.7% of what enters).
  10. GPT-3 takes 8% of its 300 B tokens from Books2 (55 B tokens). How many epochs?
    $0.08\times300/55=0.44$.
  11. What does T > 1 do in temperature mixing?
    Flattens shares: small sources get upsampled and giant web sources downweighted. $T\to\infty$ gives equal shares.
  12. Why can duplicates inflate test scores?
    Test text may also be in training, so the model has memorized it.
